# Хостинг процесу майстерні

Оновлено під код **v1.10.0**. З 04.10.2026 майстерня працює на хості https://lab.w3ir.io у публічному режимі (рішення власника: повний переїзд з ПК на хост). Цей файл — чекліст переносу і опис режимів; сам він **нічого не деплоїть**. Деплой — `deploy/series-lab/upload.sh` (SSH, ручний запуск власника).

Три різні речі, які легко сплутати:

| Що | Де зараз | Що це |
|---|---|---|
| Майстерня на ПК | `http://127.0.0.1:5344/studio/` | Той самий `server/index.mjs`. Типово `HOST=127.0.0.1`, `PORT=5344`, `npm start` |
| Публічний сайт | https://studio.w3ir.io | **Статичний** Cloudflare Pages. Лендінг, посібник і сторінки для автора. **API майстерні тут немає** — зібрано `scripts/build-site.mjs`, виклад `deploy-site.yml`. Деталі: [DEPLOY.md](./DEPLOY.md) |
| Процес майстерні на хості | **працює** на https://lab.w3ir.io (Hetzner, `OPEN_ACCESS=1 ENABLE_PAYMENTS=1 ENABLE_TELEGRAM=1`, без денної стелі витрат) | Той самий `server/index.mjs` у образі (`Dockerfile`, `HOST=0.0.0.0`, `PORT=5344`). Ім'я задає `SERIES_ALLOWED_HOSTS`. Це **не** studio.w3ir.io |

Старі нотатки казали «ядро 1.5.0» і що майстерня буває лише на ПК. Версія пакета зараз **1.9.0**. «Лише на ПК» — це типовий запуск розробки, не стеля коду: `SERIES_MODE=local` справді не слухає поза loopback, а `SERIES_MODE=public` (типово) — той самий сервер, якщо задати ім'я нижче. Твердження «на Pages немає API» **лишається правдою**.

Чи живий staging https://lab.w3ir.io уже на цьому `main`, з цього репозиторію не перевірялось. Скрипти в `deploy/series-lab/` його оновлюють, але цей чекліст їх не запускає.

## Що має бути задано на хості

Образ уже ставить `SERIES_MODE=public`, `HOST=0.0.0.0`, `PORT=5344`, `SERIES_DATA_DIR=/data`.
Решта — у файлі секретів (`lab.env` → `.env.series-lab`, локально це `.env`).

Процес **не стартує**, якщо слухає не loopback і:

- `SERIES_ALLOWED_HOSTS` порожній при `HOST=0.0.0.0` (перевірка `Host` була б вимкнена), або
- `AUTH_DOMAIN` не входить у цей список (текст входу гаманцем не збігся б з адресою в браузері). Якщо `AUTH_DOMAIN` не задано, код підставляє запасне `ai.w3ir.io` — це успадкований текст входу, не майстерня і не сайт Pages.

| Змінна | Навіщо |
|---|---|
| `SERIES_ALLOWED_HOSTS` | Ім'я, яке люди вводять. Staging-шаблон: `lab.w3ir.io`. Не `studio.w3ir.io`, доки DNS цього імені навмисно не переведено на процес |
| `AUTH_DOMAIN`, `AUTH_URI` | Той самий хост і `https://` + цей хост. Інакше SIWE не збігається зі сторінкою |
| `AUTH_SESSION_SECRET` | Сесії. Порожнє — скрипт staging зупиняється; без секрету сесія ненадійна |
| `AUTH_CHAIN_ID` | Ланцюг у тексті SIWE для EVM (типово `8453`). Solana-вхід має окремий текст і цей номер не міняє |
| `ADMIN_WALLETS` | Хто бачить Адмін. Порожній список прибирає адмінів |
| `SERIES_SPEND_CAP_USD` | Необов'язкова денна стеля витрат ключів рушіїв на весь процес. На хості `phase3.sh` ставить `off` (рішення власника 05.10.2026), див. нижче |
| `SERIES_DATA_DIR` | Каталог леджера. В образі `/data` (том, запис від uid 1000) |
| Ключі рушіїв (`FAL_KEY`, `REPLICATE_API_TOKEN`, …) | Лише ті, якими оператор готовий платити. У браузер не йдуть |
| `SOLANA_PAY_RECIPIENT` | **Публічна** адреса USDC, якщо поповнення увімкнене. Приватний ключ цього гаманця серверу не потрібен. Порожньо — оплата вимкнена (так staging і робить) |
| `SOLANA_RPC_URL` | Читання мережі для звірки переказів, якщо оплата увімкнена |
| `IRYS_PRIVATE_KEY` | Необов'язково. Окремий гаманець **з малим балансом** для кнопки Arweave в Експорті. Не гаманець творця. Без нього кнопка ховається; випуск іде з ПК |
| `LANDING_HOSTS` | На процесі майстерні лишайте порожнім. Інакше цей процес віддасть старий лендінг для імен `w3ir.io` / `www.w3ir.io`. Публічний сайт Series Lab — Pages, не цей процес |
| `HOSTING_MONTHLY_USD`, `SAAS_MONTHLY_USD`, комісії | Лише Адмін → Економіка. Див. [ECONOMY.md](./ECONOMY.md) |

Cookie сесії на не-loopback адресі стоїть з прапорцем `Secure`. Перед процесом має бути HTTPS (зворотний проксі). `AUTH_COOKIE_INSECURE=1` — лише для проби по голому HTTP, не для відкритого хоста.

`SERIES_ALLOWED_WALLETS` — запрошення. Порожньо означає «увійти може будь-який гаманець». Staging (`phase3.sh`) так не відкривається: без `ADMIN_WALLETS` і без списку скрипт зупиняється.

## Що лишається на ПК творця

Сервер майстерні не отримує ключ творця і не підписує випуск.

- Файл keypair. У майстерні **немає поля приватного ключа** і воно не додається.
- `series mint … --keypair` і `series reveal … --keypair` — команди CLI на ПК. Сервер їх не виконує.
- `series upload … --keypair` — завантаження випуску з гаманця творця. Кнопка Arweave в Експорті, якщо її увімкнути, платить з `IRYS_PRIVATE_KEY` сервера, не з цього файлу.
- ComfyUI / Automatic1111. На хості (`HOST` не loopback) вони вимкнені: процес не бачить GPU на ноутбуці творця. `SERIES_LOCAL_GPU=1` на VPS не вмикати. Хмарні рушії — ключі оператора вище.
- Підпис входу (SIWE / Phantom) лишається в гаманці в браузері. На сервер іде підпис, не ключ.

`SERIES_MODE=local` — теки репозиторію без акаунтів, лише loopback. Для хоста не використовується.

## Що свідомо не переноситься

- Приватний ключ, сид-фраза чи поле для них у студії.
- Підпис `series mint` / `series reveal` на сервері.
- Гаманець творця і гаманець виплат. `SOLANA_PAY_RECIPIENT` — лише публічна адреса.
- Заміна https://studio.w3ir.io на цей процес. Ім'я лишається за Pages, доки власник окремо не перенесе DNS.
- Живий деплой, скидання staging і виклад Pages з цього чекліста.
- Новий продукт, новий домен «на виріст» і вмикання NFT-сейфа (`VAULT_WALLET_ADDRESS` лишається порожнім).

Якщо в `SERIES_ALLOWED_HOSTS` або `AUTH_DOMAIN` потрапить `studio.w3ir.io`, процес напише попередження і все одно стартує. Це не привід вішати майстерню на лендінг.

## Як запустити той самий сервер

Перевірка ззовні: `GET /health` → `{"status":"ok","service":"series-lab"}`. Сторінка майстерні — `/login`, далі `/studio/`.

### Вузол без Docker

На машині з Node ≥ 22.13, з кореня репозиторію:

```bash
npm ci --omit=dev
# .env: SERIES_MODE=public, HOST=0.0.0.0, SERIES_ALLOWED_HOSTS, AUTH_DOMAIN, AUTH_URI, AUTH_SESSION_SECRET
npm run lab:serve
```

`npm start` ще й намагається відкрити браузер — для хоста беріть `lab:serve`. Дані лягають у `SERIES_DATA_DIR` або `data/`. Каталог має бути доступний користувачу процесу.

### Образ

```bash
docker build -t series-lab:local .
```

Зразок — `deploy/series-lab/docker-compose.yml`. Він **не** монтує `/opt/sugar` (сейф вимкнений). `SERIES_ALLOWED_HOSTS`, `AUTH_DOMAIN` і `AUTH_URI` у зразку типові для `lab.w3ir.io` і перекривають ті самі рядки у файлі секретів: міняти ім'я треба в усіх трьох. Том даних — каталог поруч із файлом (`data-next` або `SERIES_LAB_DATA`), власник **uid 1000**. Перевірка здоров'я всередині контейнера — `node`, не `wget`: в образі Alpine немає GNU wget.

`deploy/series-lab/phase3.sh` збирає той самий образ на сервері, пише `.env.series-lab` (домен `lab.w3ir.io`, оплата й Telegram вимкнені, без стелі витрат, вхід за списком) і додає блок Caddy з `Caddyfile.staging`. **Публічний режим (рішення власника 04.10.2026).** За замовчуванням `phase3.sh` лишає закритий staging. Відкрити сервіс можна прапорцями, які `upload.sh` передає на сервер:

| Прапорець | Що робить |
|---|---|
| `OPEN_ACCESS=1` | не пише `SERIES_ALLOWED_WALLETS`: увійти може будь-який гаманець. Потрібен `ADMIN_WALLETS` у `lab.env`, інакше скрипт зупиняється. Вітальні кредити видає правило `WELCOME_*` (з перевіркою балансу гаманця, потрібен RPC) |
| `ENABLE_PAYMENTS=1` | лишає `SOLANA_PAY_RECIPIENT` (публічна адреса USDC) і RPC з `lab.env`; без адреси скрипт зупиняється. Попереджає, якщо лишився `SOLANA_PAY_TEST_PACK=1` |
| `ENABLE_TELEGRAM=1` | лишає `SERIES_TELEGRAM_*` з `lab.env` |

**Стелі витрат на хості немає** (`SERIES_SPEND_CAP_USD=off`, рішення власника 05.10.2026). Вона з локальної епохи Lab (одна людина, власні ключі на ПК) і в моделі кредитів лише шкодить: коли межа вичерпана, платний користувач бачить «сервіс на денному ліміті». Економіку тримають ціни кредитів (Адмін → Економіка), а не стеля. Журнал витрат `render-log.jsonl` і оцінка вартості в інтерфейсі лишаються. Стелю можна повернути, передавши `SERIES_SPEND_CAP_USD=<usd>` у `upload.sh`.

Ліміт пам'яті контейнера staging — 512 МБ; під генерацію варто глянути `docker stats` і підняти ліміт вручну, якщо процес упирається. Скрипт запускається лише з сервера і лише за рішенням власника (`upload.sh` з ПК). Тут він не запускався.

Перед відкриттям: бекап `deploy/series-lab/backup.sh` (локально те саме — `npm run backup`). Offsite вмикає `deploy/series-lab/setup-offsite.sh` (S3-сховище, шифрування, перевірка копії назад): він сам записує `BACKUP_RCLONE_REMOTE` і `BACKUP_PASSPHRASE` у `backup.env`. Погодинні копії й перевірки відновлення описані в [DEPLOY-PLATFORM.md](./DEPLOY-PLATFORM.md#бекап).

Кроки на VPS, включно з `chown` і відкатом — [DEPLOY-PLATFORM.md](./DEPLOY-PLATFORM.md). Продукт не читає чужий `.env`: [STANDALONE.md](./STANDALONE.md).

## Публічний сайт лишається Pages

https://studio.w3ir.io і https://series-lab.pages.dev — статичні файли з `dist/site`. Workflow `.github/workflows/deploy-site.yml` викладає їх, коли змінюються тексти сайту. У цього сайту немає `/health` майстерні, ключів і генерації.

`health.yml` опитує три різні адреси, не одну майстерню:

- `lab.w3ir.io/health` — процес майстерні, якщо staging стоїть;
- `studio.w3ir.io/` — HTML лендінгу, не `/health`;
- `gen.w3ir.io/health` — інший сервіс у тому самому workflow, не Series Lab.

Свій хост майстерні в цей workflow додають окремо, коли він уже відповідає.

## Зовнішнє тестування з ПК (не хостинг)

Тунель лишає процес на комп'ютері. Це не заміна VPS.

1. Один раз: `cloudflared tunnel route dns w3ir-tunnel lab-dev.w3ir.space` (потрібен `~/.cloudflared/cert.pem`).
2. `npm run lab:tunnel`. Сервер слухає `127.0.0.1:5345`. Постійний `.env` не змінюється: `AUTH_DOMAIN`, `AUTH_URI` і `SERIES_ALLOWED_HOSTS` підставляються лише на час запуску.
3. Гаманці — у `.tunnel-wallets` або `TUNNEL_ALLOWED_WALLETS`. Без списку лишаються лише `ADMIN_WALLETS`. Порожньо назовні скрипт не відкриває.
4. `TUNNEL_SPEND_CAP_USD` (типово 5), `SERIES_LOCAL_GPU=0`, cookie `Secure`. Вітальні кредити в цьому режимі без вимоги балансу (`WELCOME_REQUIRE_BALANCE=0`).
5. Оплата USDC, якщо задано `SOLANA_PAY_RECIPIENT`, не залежить від тунелю: зарахування йде з процесу. Пакет «Тест» (`SOLANA_PAY_TEST_PACK=1`) після перевірки прибрати.

## Безпека відповідей і залежностей

- **Заголовки безпеки** (`src/security-headers.mjs`, ставляться на кожну відповідь сервера): `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` без камери, мікрофона, геолокації й платежів. `Strict-Transport-Security` (рік) додається лише коли запит прийшов по HTTPS (`X-Forwarded-Proto` від Caddy або `CF-Visitor` від Cloudflare), щоб не ламати локальний http.
- **Вкладка адмінки «Система»** (`src/sysinfo.mjs`, `GET /api/admin/system`): стан сервера в одному місці. Бекапи вона бачить через файл `backup-status.json` у каталозі даних: його пише хостовий `deploy/series-lab/backup.sh` (час, тип, результат, кількість копій, розмір, чи є зовнішня копія), а при невдалому бекапі записує `ok: false`. Ревізія образу береться з файлу `REVISION` у корені образу (`Dockerfile` копіює його, якщо він є; `upload.sh` кладе його в архів). Метрики запитів тримаються в пам'яті процесу й зникають після перезапуску, постійного сховища метрик немає.
- **Кешування статики студії** (`src/static-cache.mjs`): файли `server/ui/*` (`app.js`, стилі, переклади, `vendor/`) віддаються з `ETag` і `Cache-Control: private, no-cache`: браузер кожного разу питає, чи файл змінився, і отримує `304` без тіла (локально: 222 КБ → 0 Б), а після деплою нова версія підхоплюється одразу. `private` обов'язковий: з простим `no-cache` Cloudflare кешує файл на краю і підміняє заголовок на `max-age=14400` (виявлено 10.10.2026), тобто до 4 годин користувачі бачили б стару студію. API, картинки користувача (`/out/`, `/input/`) і сторінка входу лишаються `no-store`.
- **Завантаження студії при старті** ≈ 170 КБ зі стисненням Brotli (`app.js` 53, переклади uk 47 + en 37 + підказки 15, стилі 13), `vendor/solana-tx.js` (81 КБ) вантажиться лише на оплаті; повторні візити дають `304`. Модулі попередньо завантажуються паралельно (`modulepreload` в `server/ui/index.html`); нові модулі, які `app.js` імпортує статично, треба додавати туди ж. Друга мова ще вантажиться одразу: ліниве завантаження зекономило б ≈ 40 КБ лише на першому візиті, але зачепило б усі виклики `t()`, тому не робилось.
- **Content-Security-Policy** (`src/csp.mjs`, змінна `SERIES_CSP`): типовий режим `report`, тобто заголовок `Content-Security-Policy-Report-Only`, який нічого не блокує; порушення браузер шле на `POST /api/csp-report`, сервер пише в журнал перше входження кожного (`[csp] <директива> blocked=<адреса> doc=<сторінка>`). Режим `enforce` блокує, `off` вимикає. План: кілька днів збирати звіти з живого хоста (`docker logs serieslab | grep '\[csp\]'`), і якщо вони чисті, перейти на `enforce`.
  - Студія й решта сторінок: `script-src 'self'` (без вбудованих скриптів і без сторонніх CDN), `style-src 'self' 'unsafe-inline'`, `connect-src 'self'`, `object-src 'none'`, `frame-ancestors 'self'`.
  - Обидві політики дозволяють Cloudflare Web Analytics (`static.cloudflareinsights.com` і `cloudflareinsights.com`): скрипт вставляє сам Cloudflare на проксі-сторінки, його показав перший живий звіт 10.10.2026.
  - Сторінка входу `/login`: має вбудований скрипт-модуль, тому для неї в `script-src` дозволено `'unsafe-inline'`, а ще шрифти Google. Це відомий недолік: щоб його прибрати, скрипт входу треба винести в окремий файл.
  - Перевірено 10.10.2026 в браузері на локальній студії: 0 порушень на всіх 11 вкладках і сторінках документації, навмисне порушення дійшло до журналу. Не перевірено: сторінка входу з гаманцем, вітрина `showcase.html`, публічні сторінки колекцій. Саме їх покаже живий журнал.
- **Сторонніх CDN для коду більше немає** (10.10.2026). Раніше студія імпортувала `@solana/web3.js` з `esm.sh`, а сторінка входу `viem@2` (без точної версії, без SRI): стороння CDN на сторінках оплати й входу. Тепер це власні файли `server/ui/vendor/solana-tx.js` (лише `Transaction` з `@solana/web3.js`, версія з `package-lock.json`) і `server/ui/vendor/evm-address.js` (перевірка адреси EIP-55 на `@noble/hashes`; замінює `isAddress` і `getAddress` з `viem`). Збираються `npm run vendor` (`scripts/build-vendor.mjs`, dev-залежність `esbuild`) і комітяться; після оновлення `@solana/web3.js` чи `@noble/hashes` їх треба перезібрати. Сторінка входу за адресою підміняється при віддачі (`selfHostLoginImports` у `server/platform.mjs`). Шрифти Google на сторінці входу лишаються зовнішнім ресурсом (лише стилі й шрифти, не код).
- **`npm audit --omit=dev` (10.10.2026):** 27 попереджень, з них 5 високих. Усі в ланцюжку Solana / Irys (`bigint-buffer`, `@solana/spl-token`, `@irys/*`, `ws`), виправлень без зміни залежностей на рівні проєкту немає, а ручні `overrides` у ланцюжку підпису й оплати були б ризикованішими за саме попередження. `ws` у цьому дереві приходить з клієнтів RPC й Arweave (завантаження виконується з ПК творця), а не з вхідних мережевих з'єднань сервера.
