﻿# Головна ідея: синтез кращого з існуючих проєктів

**Формулювання власника (20.09.2026):** узяти все **краще й оптимальне** з уже наявних проєктів у контексті напряму «серії з базової картинки / рис / промптів» — і зібрати це в **новий** продукт, не розмиваючи Gremlin Family.

Це не «форкнути все» і не «переписати з нуля». Це **селекція**: що працює на практиці — заносимо в ядро; що зайве для напряму — лишаємо в донорському проєкті.

## Донори (на цьому ПК)

| Проєкт | Шлях | Роль донора |
|--------|------|-------------|
| **NFT Prompt Builder / w3ir** | `C:\Промт` (прод w3ir.io) | Універсальний конструктор колекцій, шаблони, batch, білінг/SaaS-заготовки, реф-зображення, експорти |
| **gremlin-nft** | `C:\Gremlins\gremlin-nft` (health.w3ir.io/studio) | Бойова майстерня під одну колекцію: waves, DNA, kontext-pipeline, якість, ME |
| **Gremlin Family** | той самий + бренд GFAM | **Не донор коду для ядра** — окремий продукт, який лишається в своїх межах |
| Інше (`gremlin-passport`, `gremlin-game`, …) | `C:\Gremlins\…` | Лише якщо знадобиться пізніше (ідентичність, гра) — не MVP |

Публічний знімок Промт: `nft-prompt-builder-public`. Приватний канон — папка `C:\Промт`.

## Що брати з Промт (краще / оптимальне)

| Беремо в новий продукт | Навіщо |
|------------------------|--------|
| Ідея **конвеєра** Текст → Зображення → (опційно) експорт/мінт | Зрозумілі етапи, гнучкі точки входу |
| **Шаблони колекцій** і бібліотека стилів | Швидкий старт серії без порожнього аркуша |
| **Референс-зображення (E6-логіка)** — мама тримає характер | Прямо в серце «одна мама → серія» |
| Traits з **вагами** + зважене семплування без дублікатів | Рідкість і унікальність |
| **Batch** промптів / зображень з чекпоінтами й бюджетом | Масштаб 200…10k без героїзму |
| Експорт ZIP під кілька цілей (Metaplex / Candy Machine / generic) | Випуск як режим, не як єдиний шлях |
| Image-to-Prompt / куратор / Prompt-Lock (як ідеї) | Міст «є картинка → є формула» |
| Операційна зрілість: ключі-шаблон, UA/EN, доки оператора | Менше хаосу на старті |
| Content-safety, каскад двигунів (як опції) | Надійність у проді |

| Не тягнемо в MVP (лишається в Промт / пізніше) | Чому |
|-----------------------------------------------|------|
| Повний SaaS: кредити, Helio, рефералка, адмін-економіка | Інший продукт і регуляторика |
| Обов’язковий Thirdweb/Crossmint у день один | Спочатку лабораторія серій |
| Увесь Streamlit-моноліт «як є» | Новий продукт має свій каркас; ідеї — так, копипаста UI — ні |
| Showcase/бета w3ir як бренд | Новий продукт — окрема назва (див. BRAND.md) |

## Що брати з gremlin-nft (краще / оптимальне)

| Беремо | Навіщо |
|--------|--------|
| Ланцюг **traits → buildRecipes → prompt** | Закон серії; архів traits+prompt |
| **Seed / DNA / унікальність** до рендеру | Дешева гарантія «не зліпились» |
| **Хвилі** (нова поставка не ламає стару) | Масштаб без перепису канону |
| Шаблон промпту Keep / Change / **Also add** (EXTRA_KEYS) | Стабільна структура, зручний архів |
| Одна (або фіксовані) **базові картинки** + kontext/strength | Мама як якір |
| Студійні практики: пілоти «перші N», відбір ✓/↻, версії, кошик | Дисципліна якості |
| Рідкість statistical + буст тірів (як опція випуску) | Коли серія стає колекцією |
| Гейти якості / critic / reject queue (полегшені) | Не палити бюджет на брак |
| Audit / render-log / денні знімки стану | Відтворюваність і довіра |
| Мультидвигуни за одним контрактом (kontext, openai, …) | Порівняння на тих самих рецептах |
| CI + тести на інваріанти рецептів | «Оптимальне» = те, що не ламається тихо |

| Не тягнемо в ядро нового продукту | Чому |
|-----------------------------------|------|
| Бренд, lore, імена, Creator Hub **Gremlin Family / GFAM** | Окремий продукт |
| Жорсткий розмір 333 і зарезервовані Father/Mother як єдиний шлях | У новому — довільна мама й size |
| Прод health.w3ir.io/studio як єдиний деплой | Може бути інший хост/домен |
| Увесь мінт-стек Sugar «з коробки» в MVP | Фаза «випуск», не старт |

## Оптимальна збірка (цільовий профіль)

```
З Промт:     мама/реф + шаблони + batch + експорт-цілі + ops-звички
З gremlin:   DNA/хвилі/структура промпту + студія якості + детермінізм
Мінус:       SaaS-білінг і GFAM-канон у MVP
Дорівнює:    новий двигун серій (series-studio)
```

Критерій «оптимально»: **мінімум ручної праці на N унікальних промптів**, **повторюваний seed**, **одна мама тримає серію**, **архів переноситься**, **випуск колекції — свідомий режим**.

## Як вирішувати суперечки між донорами

1. Якщо фіча є в обох — беремо **простіший контракт даних** + **бойовий інваріант** (тести/DNA).
2. Якщо фіча лише в Промт і тягне білінг/гаманці — відкладаємо після локального MVP.
3. Якщо фіча лише в gremlin і прив’язана до GFAM-текстів — **узагальнюємо** (пресет), не копіюємо lore.
4. Новий код пишемо під `series-preset` / `series-archive`, а не під внутрішні шляхи `out-v2` чи `data/workspace/<wallet>`.
