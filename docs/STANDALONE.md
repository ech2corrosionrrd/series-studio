# Series Lab — окремий самодостатній продукт

Оновлено: **05.10.2026**

## Рішення

Series Lab — **окремий продукт з власною історією, даними, конфігурацією й сервісами**. Він не залежить від жодного іншого проєкту.

## Що в Series Lab своє

| Ресурс | Де |
|---|---|
| Леджер кредитів | `data/users.db` (локально) · `/opt/series-lab/data-next/users.db` (staging): створюється порожнім самим Lab |
| Дані гаманців | `data/users/<гаманець>/` |
| Секрети й налаштування | `.env` (локально) · `/opt/series-lab/lab.env` (staging) — заповнює власник; жодного файлу з іншого проєкту |
| Оплата | USDC у Solana на адресу `SOLANA_PAY_RECIPIENT` ([ECONOMY.md](./ECONOMY.md)) |
| Бекапи | `npm run backup` → `backups/` ([GUIDE.md](./GUIDE.md#бекап)) · на сервері `deploy/series-lab/backup.sh` (cron), лише дані Lab |
| Розгортання | `deploy/series-lab/*`: власний образ, каталог, `.env.series-lab` із `lab.env`; [DEPLOY-PLATFORM.md](./DEPLOY-PLATFORM.md) |
| Історія змін | цей репозиторій · [CHANGELOG.md](../CHANGELOG.md) |

## Єдина спільна інфраструктура

Якщо Lab стоїть на одному хості з іншим сайтом, скрипт розгортання торкається лише: docker-мережі та **одного блоку reverse-proxy** для `lab.w3ir.io` (`deploy/series-lab/Caddyfile.staging`). З `SKIP_CADDY=1` скрипт лише друкує блок, і ви додаєте його самі. Вмісту чужих проєктів скрипти не читають.

## Що лишилось «сумісним», але не обов'язковим

- **Партнерські API** `/gremlin/*`, `/api/v1/generate/tma`, `/api/v1/tma/contract`, `/api/vault/status` — для Passport і Telegram-міні-застосунку; працюють, якщо задано ключі (`GREMLIN_API_KEY`, `TMA_API_KEY`), і не потрібні для решти продукту.
- **Знімок сумісності** (`test/fixtures/compat-snapshot.json`) закріплює формат сесійних токенів, реферальних кодів, промптів, тарифів. Це знімок поведінки, а не залежність від живої системи. Юридичні сторінки в ньому вже описують оплату USDC у Solana.

## Відкриті рішення

1. **Скидання staging** (потребує дій на сервері): `CONFIRM=yes bash deploy/series-lab/reset-staging.sh` (або копія на сервері), далі `upload.sh` з `lab.env` Lab.
2. **Юридичні тексти** (`server/site/LEGAL.md`, `UMOVY.md`): назва оператора та умови — затвердити окремо.
3. **NFT-сейф / Дроп #2** (`vault.mjs`): **поза ядром продукту, відкладено і лишається вимкненим.** Бачення ([PRODUCT.md](./PRODUCT.md)) — людина деплоїть і виставляє сама; Lab не розсилає NFT покупцям. API `/api/vault/status` і таблиця `nft_fulfillments` є, фоновий reconcile **не стартує** без `VAULT_WALLET_ADDRESS`. Тригера видачі після оплати немає. Не вмикати в межах поточного продукту.
4. **Ім'я процесу** (`SERIES_ALLOWED_HOSTS`, `AUTH_DOMAIN`, `AUTH_URI`) — рішення власника на момент викладу. Шаблон staging лишає `lab.w3ir.io`. `studio.w3ir.io` цим не замінювати: це сайт Pages.
