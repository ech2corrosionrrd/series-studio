﻿# Бачення продукту (чернетка New Bot, 20.09.2026)

## Головна ідея власника

**Узяти все краще й оптимальне з існуючих проєктів** (насамперед `gremlin-nft`) у контексті напряму серій — і зібрати новий продукт, не розмиваючи GFAM.

Це не ТЗ і не обіцянка фіч — рамка, якою я б орієнтувався, будуючи цей продукт поруч із Gremlin Family.

## В одному реченні

**Серійний комбайн для image-моделей з референсом:** ти даєш одну «базову картинку серії», словник рис і правила промпту — отримуєш детерміновану пачку рецептів, промптів і (за бажанням) картинок, яку можна архівувати, порівняти й пізніше випустити як колекцію.

## Навіщо він існує

Головне для серій — швидкість («крутанув — подивився») разом із дисципліною: унікальність, рідкість, метадані, повторюваність.  
Gremlin-nft сильний у дисципліні, але заточений під **одну** колекцію й бренд.

Дірка між ними: людині потрібен інструмент «зроби мені серію з цієї бази», без зобов’язання одразу мінтити GFAM і без ручного копіювання 500 промптів.

## Що це є / що це не є

| Є | Не є |
|---|------|
| Двигун серій (лабораторія → опційно випуск) | Ще одна версія Gremlin Family |
| Пресет + архів як першокласні артефакти | Чат-бот «напиши промпт» |
| Traits → recipe → prompt як закон | Промпт як єдине джерело правди |
| Одна мама на серію в MVP | Генератор «з нуля без рефа» як ядро |
| Локальний/self-hosted спочатку | Ончейн-перший продукт |

## Північна зірка UX

1. Відкрив серію (або імпортував пресет).
2. Поклав / обрав материнську картинку.
3. Підкрутив риси або взяв шаблон.
4. Натиснув «зібрати N» → бачиш рецепти й промпти.
5. «Пілоти» → відбір → повний прогін.
6. Експорт архіву (і за потреби бандлу під маркетплейс) — окрема свідома дія «випуск».

Якщо крок 6 змішати з кроком 1 в одному «Mint now» — продукт знову стане клоном GFAM-студії.

## Архітектурне бачення

```
preset (base + traits + promptTemplate + seed + size)
        ↓ buildRecipes
recipes[] (traits + prompt + dna)
        ↓ render (engine)
images[] + logs
        ↓ optional
archive / metadata / marketplace bundle
```

Усе, що вище `render`, має працювати **без API-ключів** (чистий текст/JSON). Це дає відтворюваність gremlin-nft.

## Диференціація

- Від Midjourney/чату: серія, seed, унікальність, експорт структури.
- Від чистих trait-генераторів PFP (без рефа): мама/kontext-стиль — характер тримається.
- Від gremlin-nft: будь-який бренд/серія за 10 хвилин, GFAM не чіпаємо.

## Принципи продукту

1. **Канон чужої колекції священний** — GFAM окремо.
2. **Пресет важливіший за UI** — UI можна переписати; JSON-контракт ні.
3. **Детермінізм за замовчуванням** — той самий seed = ті самі рецепти.
4. **Архів — валюта переносу** між студією й майбутнім репо.
5. **Випуск колекції — режим, не домашня сторінка.**
6. **Спочатку користь на одному ПК**, веб — коли локальний цикл вже кайфовий.

## Успіх через 3 місяці (якщо піде)

- Є окреме репо й робоча назва/домен.
- З пресета без ручного копипасту збирається серія 50–200 промптів.
- Імпорт/експорт архіву відкривається в інструменті й (ідеально) читається в інших інструментах.
- Зроблено ≥1 тестову серію не-GFAM «від мами до пілотів».
- Беклог GFAM не зупинявся через цей продукт.

## Успіх через 12 місяців (амбіція)

- Студія серій як звичний інструмент для нових дропів / спінофів.
- Опційний шлях «лабораторія → колекція» з рідкістю й бандлом.
- Пресет-формат — внутрішня «мова» між твоїми проєктами на ПК.

## Моє ставлення до ризиків

Найбільший ризик — почати з домену, лендінгу й ME, доки не болить відсутність пресета.  
Другий — розмити GFAM.  
Третій — зробити «ще один чат з картинками» без DNA/унікальності — тоді немає сенсу тягнути уроки з gremlin-nft.

Тому я б будував вузько: **пресет → рецепти → архів → пілоти**, і лише потім бренд/домен/веб/ончейн.
