﻿# Ідеї напряму

## Ядро

- Універсальний двигун: **1 базова картинка серії → словник рис → seed → N рецептів → промпти → картинки**
- Переносний **архів структури промпту** (Keep / Change / Also add + ключі рис)
- Хвилі / серії з власним base, не ламаючи попередні номери іншої колекції
- Два режими продукту пізніше: *лабораторія* і *випуск колекції*

## Міст з існуючих проєктів

- З gremlin-nft: детермінізм DNA, унікальність, рідкість, reject queue, експорт
- Спільний JSON-пресет, щоб не копіпастити промпти між папками

## Продуктові ідеї

- Бібліотека пресетів (серії як карти в UI)
- «Спін-оф»: новий base + той самий шаблон промпту
- Порівняння двигунів (kontext / openai / …) на одних і тих самих рецептах
- Експорт «лише тексти» vs «тексти + png»
- Мультимама пізніше (A/B рефи) — не в MVP

## Ризики / анти-ідеї

- Один UI і для мінту GFAM, і для пісочниці — легко отруїти канон
- Промпт як єдине джерело правди без traits — роз’їзд з метаданими
- Ранній ончейн/ME до стабільного візуалу серії

## Доповнення: бачення в ідеях (New Bot)

Детальніше — у [VISION.md](VISION.md). Нижче — конкретні ідеї, які з нього випливають.

### Продукт / позиціонування

- Робочий ярлик до бренду: «Series Studio» / «двигун серій»; фінал — у BRAND.md
- Слоган-кандидат: «One base. Many recipes.» / «Одна мама — серія промптів»
- Два тарифи цінності пізніше: *лабораторія* (текст+пілоти) і *випуск* (метадані/бандл) — навіть якщо поки все безкоштовно для себе

### UX / потоки

- Майстер «Нова серія»: мама → шаблон промпту → риси (імпорт або порожній) → seed → size
- Вкладка «Рецепти» як таблиця: #, line, DNA short, traits chips, prompt preview
- «Пілоти»: перші N / вибіркові номери / лише змінені після правки traits
- Diff архівів: що змінилось у промптах між seed A і seed B
- Режим «лише тексти» (без витрачання API) для верстки словника рис

### Дані / інтероперабельність

- `series-preset/v0` і `series-archive/v0` як спільний формат обміну
- Опційний імпорт «плоского» списку промптів → reverse не обіцяти; краще завжди йти від traits
- Знімок пресета в git або в `presets/` — серія як файл, не як стан у голові
- Overrides на окремі index (як у gremlin-nft) — точечні правки без пересідання всієї хвилі

### Технічні ідеї (після контракту)

- CLI: `series build`, `series archive`, `series pilots`
- Плагіни двигунів (kontext, openai, …) за тим самим контрактом, що в gremlin-nft
- Перевірка унікальності DNA до рендеру (дешево)
- Легкий critic / reject queue — запозичити пізніше, не в день один
- Локальний веб лише коли CLI+папка вже звичні

### Ідеї «на виріст»

- Мультимама / A-B рефи на одну серію
- Бібліотека публічних пресетів (без чужих брендів)
- Командний режим: кілька людей правлять traits, seed lock у власника
- Експорт під кілька маркетплейсів одним бандлом-адаптером
- «Серія як датасет» для донавчання / LoRA — окремий етичний і ліцензійний трек

### Анти-беклог (свідомо ні)

- Автомінт у GFAM Candy Machine
- Імена / lore Gremlin у дефолтному шаблоні нового продукту
- Обов’язковий Discord/роялті до першої чужої серії
- Хмара як єдиний спосіб роботи без локального архіву
