# Послідовність етапів Series Lab

Кожен етап має **оптимальний** набір (те, що роблять майже завжди) і **широкий** (розширений спектр / advanced).  
Поля з попереднього етапу **не дублюємо** — лише читаємо або повертаємось на відповідну вкладку для внесення правок.

Термінологія: **базова картинка(и) серії**; `primary` = головна базова.  
Пояснення простими словами для кожного етапу — [GUIDE.md](./GUIDE.md), вкладка «❓ Довідка» і сторінка етапів на цьому ПК (`http://127.0.0.1:5344/studio/docs/stages/`).

| # | Етап | Оптимально | Широкий спектр (Advanced) | Не робимо тут |
|---|------|------------|---------------------------|---------------|
| 1 | **Огляд (Overview)** | Назва, id, розмір, seed, двигун / сила; галочка «База — частина колекції (видання #0)»; «Почати серію» / «Зберегти» / «Спін-оф». | Автоматичне відновлення workspace (`workspace/current.json`). | Промпти, трейти, запуск рендеру. |
| 2 | **Основа (Base)** | Головна базова картинка (`primary.png` через upload або wish→generate). Вона ж нижній шар «Скласти шари». | Лінійні бази (`base-<line>.*`), додаткові рефи (`style-*`, `extra-*`), 🤖 **Vision Assist**. | Назва/розмір/seed, мінт. |
| 3 | **Конструктор (Constructor)** | Шаблон промпту, пак рис, **редактор опцій**, `styleLock`. Галочка `skipDna`: шар малюється, у DNA не входить. | Бібліотека паків, матриця LoRA / тегів під різні двигуни. Файли шарів — `layers/<ключ>/<значення>.png` (окремого поля шляху в таблиці немає). | Повторення параметрів ідентичності. |
| 4 | **Рецепти (Recipes)** | «Зібрати тексти» (без кредитів), таблиця DNA, diff-seed, рідкість. | Хвилі поставки, diff двох архівів, точкова правка (`overrides`), синергія рис. | Завантаження картинок, оплата. |
| 5 | **Генерація (Generate)** | «12 пілотів — порахувати» / оцінка → генерація; DNA-блок. «Скласти шари» з готових PNG поруч із промптами: шари завантажуються одним ZIP (`<риса>/<значення>.png`) у картці «Шари PNG» з покриттям серії. | Паралельність, режими selection, SSE, `mock`, межа витрат, автостоп, версії. | Зміна структури ДНК / серії. |
| 6 | **Відбір (Review)** | keep / redo, версії `v·N`, redo marked. «Видалити» → кошик (відновлення на цій вкладці). «Прибрати з набору» лишає файл у версіях. | Порівняння наборів, AI Triage, «Знайти схожі». | Публічний мінт / клейм. |
| 7 | **Експорт (Export)** | **Архів випуску** («Перевірити чекліст» → «Зібрати ZIP», за бажанням лише позначені «Лишити») → портал запуску. ZIP для майданчика; мінт ним не запускається. | Інші ZIP-профілі, CSV, Arweave (Irys), вітрина, датасет LoRA, хаб випуску. | Прямий ончейн-мінт з цієї вкладки. |
| — | **Деплой** | «Зібрати набір деплою» (приховані файли, для Solana — список дозволених). Далі на ПК: `release-init` → `upload` → `hidden` → `guards` → `mplx cm create` → `verify` → `series mint --keypair` → `series reveal --keypair`. | EVM: пакет Thirdweb; розкриття лишається в кабінеті. Ordinals: інструкція, спочатку signet. Sugar — пункт «Solana (Sugar, застарілий)», файли в `sugar/`; `series mint` його не збирає. | Підпис у браузері і приватний ключ у полі. |
| — | **Маркет** | «Зібрати набір маркетплейсу». Solana: Magic Eden і Tensor. EVM: OpenSea. Bitcoin: Ordinals. | Розміри банера, аватара й обкладинки в `SIZES.json`. | Лістинг через API майданчика. |
| — | **Адмін** | Ресурси (ключі, кошик), **Економіка**, статистика, помилки. | Перевірка рушіїв. У public — гаманці з `ADMIN_WALLETS` (якщо змінну не задано — типовий оператор). | Показ секретів ключів. |
| — | **Довідка** | Путівник 1 → 7, далі Деплой (команди мінту й розкриття) і Маркет (продаж), швидкий старт, страховка, словник, FAQ. | CLI, перелік docs. | — |

## Принцип руху по майстерні

- **Рух по кроках** 1 → 2 → 3 → 4 → 5 → 6 → 7, далі вкладки «Деплой» і «Маркет». Прямі вкладки лишаються.
- Повернення назад — лише у випадку необхідності змінити першоджерело даних (Огляд для seed/size, Основа для базового референсу, Конструктор для правил промпту).
