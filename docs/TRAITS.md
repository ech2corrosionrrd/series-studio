# Traits · Бібліотека паків, знімок у пресеті та Prompt Matrix

## 1. Дві ролі трейтів у Series Lab

| Де | Що це | Характер даних |
|----|--------|----------------|
| `libraries/traits/*.json` | **Каталог паків** (глобальна бібліотека рис) | Спільна база знань, джерело для операції «Застосувати пак» |
| `preset.traits.items` | **Знімок (snapshot)** у файлі конкретної серії | Автономна копія, що зберігається в `presets/<id>.json` |

**Головне правило**: Застосування пака створює глибоку копію `items` у чернетку пресету. Подальші модифікації у бібліотеці не ламають уже збережені серії.

---

## 2. Схема пака (`series-trait-pack/v0`)

```json
{
  "schema": "series-trait-pack/v0",
  "id": "pfp-core",
  "name": "PFP core",
  "description": "Базовий каталог портретних рис для PFP колекцій",
  "tags": ["pfp", "portrait"],
  "items": [
    {
      "key": "hair",
      "type": "string",
      "options": [
        { "value": "Buzz Cut", "weight": 5, "prompt": "buzz cut hair" },
        { "value": "Afro", "weight": 3, "prompt": "stylish afro hairstyle" }
      ]
    }
  ],
  "defaults": {
    "changeKeys": ["hair", "outfit"],
    "extraKeys": ["eyewear", "headwear"]
  }
}
```

---

## 3. Вбудовані паки рис (`libraries/traits/`)

1. **`pfp-core`** — класичний портретний PFP baseline: зачіска, колір волосся, вираз обличчя, окуляри, одяг, аксесуари, тон шкіри, фон.
2. **`brand-mascot`** — векторні маскоти та персонажі: силует, основний колір, акцент, поза, реквізит, спрощений фон, емоція.
3. **`fine-art`** — художні полотна: техніка (олія, акварель), палітра, мазки, композиція, світлотінь, атмосфера.
4. **`abstract-series`** — абстрактні генеративні форми: геометричні фігури, патерни, фактури, кольорові поля, ритм, контраст.

---

## 4. Керування паками рис (Trait Pack Library Manager)

- **Збереження в бібліотеку**: збереження поточного набору трейтів у `libraries/traits/<id>.json` через UI або `POST /api/trait-packs/save`.
- **Експорт з пресету**: `POST /api/trait-packs/export-from-preset` для швидкого створення нового пака на основі готової серії.
- **Видалення**: `DELETE /api/trait-packs/:id`.

## 5. Редактор опцій рис (Trait Options Editor)

У вкладці **Конструктор** доступна інтерактивна таблиця опцій обраного трейту:
- **`value`**: назва варіанту (наприклад, `Neon Mohican`).
- **`weight`**: вага ймовірності випадання (ціле або дробове число $\ge 1$).
- **`prompt`**: фрагмент промпту англійською мовою, який підставляється в генератор.
- **`layer`** (необов’язково, у JSON опції): відносний шлях PNG у теці шарів, якщо файл не лежить у `layers/<ключ>/<значення>.png` (у ZIP-завантаженні такий PNG має лежати за цим відносним шляхом, до 3 рівнів теки). Шлях без `..`. `series compose` і кнопка «Скласти шари» кладуть цей PNG поверх базової картинки. `None` шар не малює. Генерація промптами лишається. Таблиця опцій у Конструкторі цього поля не показує; правка рядка в таблиці ключ `layer` не зберігає. Типовий шлях від таблиці не залежить.
- **`exact`** (колонка «рівно N»): скільки разів опція має зустрітися на всю серію. Це рівні рідкості: **1 — це 1/1**, 2 і більше — рідкісний «грааль»; решта кадрів іде за вагами. Рецепти збирає двигун так, що число виконується точно, або збірка падає з назвою риси; сума «рівно N» однієї риси не може бути більшою за розмір серії. Кнопка **1/1** у рядку опції ставить `exact: 1` і знімає його повторним натисканням; під таблицею рядок показує, скільки кадрів закріплено. Такі кадри варто підготувати вручну або перевірити особливо уважно.
- **`skipDna`** (на рисі, галочка «Цей шар не входить в DNA»): шар усе одно малюється, але в DNA не входить. Типово вимкнено.
- **`layerOnly`** (на рисі, галочка «Критична риса: малюється шаром PNG»): риса не потрапляє в промпт для ШІ (ні в `changeKeys`, ні в `extraKeys`), її малює лише ваш шар PNG у гібридному режимі. DNA, вага й рідкість не змінюються: значення випадає як звичайно. Картка «Шари PNG» показує, яких шарів критичних рис ще бракує. Типово вимкнено; поле необов’язкове, старі пресети працюють без змін.
- **`layerOffset`** (на рисі, поля «Зсув шару по X/Y, px», необов’язково): `{ "x": 12, "y": -8 }`, цілі пікселі кадру, X вправо, Y вниз. Зсуває шар цієї риси на кожному кадрі. Потрібен, коли ШІ-рушій перемалював обличчя вище чи нижче, ніж у базі: шар, намальований за базою, лягає повз потрібне місце (прогін 25.10.2026, `ENGINES.md`, розділ 9). Що виходить за кадр, відкидається. Підбирати так: зберегти пресет і натиснути «Переглянути кадр» у картці «Шари PNG». Без поля шар лежить там, де намальований.
- **Зсув на кадр** (поля «Зсув цього кадру по X/Y, px» біля «Переглянути кадр» на вкладці «Генерація»; файл `layer-offsets.json` у теці набору, `{ "<видання>": { "x": 7, "y": -3 } }`): `layerOffset` рухає шар риси однаково на кожному кадрі, а модель рідко зсуває всі кадри однаково, і два набори від різних прогонів зсуваються по-різному, тому поправка для одного кадру зберігається **разом із набором кадрів**, а не з пресетом. Додається до зсуву риси й до підгонки `layerAlign`; діє в перегляді й у «Скласти шари» (і в `series compose --over <набір>`, і в `--preview`) лише коли шари накладаються на набір кадрів. Цілі пікселі кадру, ±2000; 0 і 0 знімає. Без файлу все працює як раніше.
- **`layerAlign`** (на рисі, галочка «Підганяти шар під кадр моделі», необов’язково): `true`. Шар намальовано на базовій картинці, а модель зсунула й трохи змінила масштаб кадру; з галочкою Лабораторія порівнює контури кадру з базою (оператор Собеля, нормована кореляція, спершу грубо, потім точно), знаходить один спільний зсув і масштаб і застосовує їх до шару перед накладанням. Працює лише в гібриді й лише коли відома база: `series compose --over <набір> --base <png>`, а в Лабораторії база береться з поточної картинки серії. Це не розпізнавання обличчя: знаходиться один глобальний зсув із масштабом, а не зміна пози чи пропорцій обличчя. На 6 кадрах Kontext (прогін 25.10.2026) знайдено зсув 5–21 px по X, 16–32 px по Y і масштаб 0,94–0,98; кільце, намальоване за базою, лягло ближче до потрібного місця (на кадрі 4 відстань до ока була 125 px без підгонки, 103 px з нею, у базі 110 px), але не точно: модель змінила пропорції обличчя, і залишок порядку 10 px лишається. Оцінка на око, на одній точці й одному кадрі. Слабкий збіг (кореляція нижче 0,3), інші пропорції кадру й бази чи кадр без контурів: шар лишається там, де намальований, причина в полі `align` перегляду кадру й у `dna.json` (`low_match`, `shape`, `flat`, `no_base`). Ручний `layerOffset` додається зверху після підгонки. ≈ 150 мс на кадр. Без поля нічого не змінюється.
- **Звідки взяти таблицю рис.** Не обов'язково вводити риси вручну: «Створити риси з шарів» будує їх із теки шарів (див. [STUDIO-UI.md](./STUDIO-UI.md)), а CSV (`trait,value,weight,prompt,exact,layer`) дозволяє правити ваги в таблиці. Вага з імені файлу: `Cap#20.png` це значення `Cap` з вагою 20; без `#` вага 10.
- **`backdrop`** (на варіанті, `#rrggbb`, у JSON або в колонці CSV `backdrop`): колір фону кадру, який не вдається отримати від моделі (прогін 25.10.2026: «teal» дав майже чорне темно-синє полотно). Під час складання кадру фон шукається на самому кадрі й перефарбовується зі збереженням яскравості, без моделі й безкоштовно (≈ 300 мс на кадр). Працює лише для гладкого студійного фону: де його не знайдено (хмари, стіна, текстура), кадр не змінюється, а причина (`not_smooth`, `no_backdrop`, `whole_frame`) записується в `skipped` як `tint:<риса>/<значення>`. Застосовується в «Скласти шари» і в гібриді, перед накладанням шарів. Без поля нічого не змінюється.
- **`z`** (на рисі, поле «Порядок шару», необов'язкове число): порядок накладання шарів PNG знизу вгору. Менше число лежить нижче, більше вище. Без `z` риса бере своє місце в пресеті (тож пресет без жодного `z` малює як раніше); рівні числа йдуть у порядку пресету. Діє для `series compose` (як `--base`, так і `--over`) і «Скласти шари». Міняє лише піксели: DNA, порядок рис у пресеті й промпти не змінюються.
- Кнопки: **Add Option**, **Delete**, **Duplicate Option**.

## 6. Правила конфліктів трейтів (`rules.conflicts`)

Для уникнення візуально несумісних поєднань (наприклад, шапка `Beanie` поверх пишного `Afro Short`) задаються правила конфліктів:

```json
"rules": {
  "conflicts": [
    {
      "a": "headwear:Beanie",
      "b": "hair:Afro Short",
      "note": "Шапка Beanie візуально обрізає об'ємне волосся Afro"
    }
  ]
}
```

При спробі зберегти конфліктну комбінацію в редакторі рецепта API повертає `400 Bad Request` з детальним описом конфлікту.

## 7. Multi-Engine Prompt Matrix & LoRA Tags

Пресет підтримує блок `engineMatrix` для адаптації промптів під різні AI-генератори:

```json
"engineMatrix": {
  "flux": { "trigger": "gremlin_character_v2", "suffix": "8k photorealistic" },
  "sdxl": { "lora": "gremlin_style:0.85", "qualityTags": "masterpiece, highly detailed" },
  "midjourney": { "params": "--v 6.1 --stylize 250 --ar 1:1" }
}
```

Модуль `src/matrix.mjs` автоматично форматує вихідні промпти під цільовий рушій:
- **Flux**: підставляє тригерні токени та формує природний опис.
- **SDXL**: огортає у формат `<lora:name:weight>` та додає quality tags.
- **Midjourney**: очищає службові теги та додає параметричні прапорці `--v 6.1 --stylize`.
- **OpenAI / Kontext**: генерує чистий descriptive промпт.
