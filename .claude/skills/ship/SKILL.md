Виконай ланцюжок для поточних змін. Якщо зміна велика (нова функція, платежі, ключі, сховище, схема даних) - зупинись і запропонуй гілку та PR (див. розділ Git у CLAUDE.md).

1. `git status --short` і `git diff --stat`: переконайся, що в коміт іде лише потрібне. Секрети (`.env`, ключі) ніколи не додавай.
2. Документація до коміту (таблиця в CLAUDE.md): видима зміна - рядок під `## [Unreleased]` у `CHANGELOG.md` і профільні документи.
3. `npm run ci` - усе має бути зеленим. Червоне - виправ причину, не пропускай (`SKIP_CI`/`SKIP_DOCS_CHECK` лише за прямою вказівкою).
4. Коміт українською у стилі `fix:` / `feat:` / `docs:`, з рядком `Co-Authored-By` з системної вказівки.
5. `git push origin main` (хук pre-push ще раз ганяє `npm run ci`).
6. Якщо змінились файли сайту (`server/ui/locales/**`, `scripts/*site*`, `scripts/legal-pages.mjs`, `scripts/inline-md.mjs`, `docs/legal/published/**`, `package.json`): `gh run list --workflow deploy-site.yml --limit 1`, потім `gh run watch <id> --exit-status`, і перевір `https://studio.w3ir.io` (`/`, `/en/`, `/terms/`, `/privacy/` дають 200; на юридичних сторінках немає `__cf_email__`).
7. Звіт: коміт, результат ci, результат деплою, що перевірено, а що ні.

Не роби без окремої згоди: платні виклики генерації, зміни ключів, видалення даних.
