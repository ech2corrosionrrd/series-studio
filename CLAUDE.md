# Правила проєкту Series Lab

Для людей і для агентів, що працюють у цьому репозиторії.

## Документація — до коміту, не після

**Перед кожним комітом документація має відповідати коду.** Коміт, що міняє поведінку без оновлення документів, не приймається.

Що оновлювати разом із кодом:

| Змінили | Оновіть |
|---|---|
| CLI-команду чи прапорець (`bin/series.mjs`) | `README.md` (розділ CLI), `docs/GUIDE.md` (таблиця команд), довідку в `server/ui/locales/*` |
| HTTP-маршрут (`server/index.mjs`) | `docs/API.md` |
| Змінну `.env` (`.env.example`) | `README.md` (таблиця змінних) або профільний документ |
| Поведінку вкладки, поле, підказку | `docs/STUDIO-UI.md` / `docs/EXPORT.md` / `docs/STAGES.md` і обидві локалі (uk + en) |
| Шлях випуску, сховище, деплої | `docs/RELEASE.md`, `docs/EXPORT.md`, `docs/ROADMAP.md` |
| Будь-що видиме користувачу | рядок під `## [Unreleased]` у `CHANGELOG.md` |
| Новий файл у `docs/` | рядок в індексі `docs/README.md` |
| Версію в `package.json` | рядок «Стан: vX.Y.Z» у `docs/README.md` |

Видалений постачальник (Pinata) не має лишатись у живих документах і коді. Історичні згадки дозволені лише в `CHANGELOG.md`, `docs/ROADMAP.md`, `docs/RECOMMENDATIONS.md`, `docs/QUALITY-REVIEW.md`.

### Як це перевіряється

- `npm run docs:check` — офлайн-перевірка розбіжностей: команди CLI, маршрути API, змінні `.env.example`, індекс документів, версія, видалені постачальники.
- `test/docs.test.mjs` запускає ту саму перевірку в `npm test` і в `npm run ci`.
- Хук `.githooks/pre-commit` додатково вимагає, щоб у коміті з правками `src/`, `server/`, `bin/`, `scripts/` чи `package.json` були й документи та `CHANGELOG.md`.
  Увімкнути в новому клоні: `git config core.hooksPath .githooks` (вмикає й `pre-push`).
  Чистий рефакторинг без видимих змін: `SKIP_DOCS_CHECK=1 git commit …` (використовувати свідомо).
- Скрипт не оцінює зміст. Дотримання змісту (що текст правдивий) — відповідальність автора коміту.

## Тести й перевірки перед комітом

Швидко: `npm run ci` — одна команда для 1–3 нижче і `audit:api` (замінила GitHub CI; хук `.githooks/pre-push` запускає її перед push, пропуск: `SKIP_CI=1`). Окремо:

1. `npm test` — усе має бути зеленим.
2. `npm run audit:i18n` — ключі uk і en збігаються.
3. `npm run audit:ui` — немає id, що згадані в коді, але відсутні в HTML.

## Мова і підказки

- Видимий текст — у `server/ui/locales/uk.js` і `en.js`, обидві мови одночасно.
- Підказки й поля залежать від обраного варіанта: показується лише те, що стосується вибору (профіль, мережа). Не показувати поради іншої мережі.
- Термін «базова картинка серії»; ніколи «мати» / mother у інтерфейсі.

## Ключі й гроші

- Приватні ключі гаманців не передаються в Lab, на сервер і в чат. Підпис і оплата — на ПК користувача (`series upload --keypair`).
- Серверні платні ключі (`IRYS_PRIVATE_KEY` тощо) — окремий гаманець з малим балансом; у тестах і smoke вони блокуються.
- Оплата кредитів — USDC напряму в Solana, без посередника.

## Сховище

Arweave через Irys. Pinata не використовується. Завантаження для випуску — `series upload` (відновлюване, з `cache.json`).

## Git

- Коміти українською у стилі `fix:` / `feat:` / `docs:`.
- **Малі зміни** (тексти, документація, конфіги, фікс на 1–2 файли без зміни поведінки): коміт прямо в `main` і `git push`. Хук `pre-push` ганяє `npm run ci`; деплой сайту автоматичний.
- **Гілка від `main` і PR** — для нових функцій, змін платежів, ключів, сховища чи схеми даних і всього, що власник хоче переглянути до мерджу. Одна гілка на задачу, не на кожну спробу.
- Власник дає одну дозволяючу фразу («зроби і задеплой») — тоді весь ланцюжок (коміт, push, деплой, перевірка) виконується без покрокових питань і закінчується звітом. Зупинка лише для незворотного чи платного: платні виклики генерації, ключі, видалення даних.
- Перед виправленням знайти причину в коді, а не пробувати припущення.
