## 3. Що ШІ **не** робив (заповніть за фактом)

- [ ] не складав і не підписував документи від імені автора без його перегляду;
- [ ] не підставляв вигаданих джерел: усі джерела з переліку відкриті автором;
- [ ] не отримував доступу до приватних ключів, seed-фраз і платіжних даних автора (за правилами проєкту ключі не передаються в чат, на сервер і в Lab);
- [ ] не виконував злиття змін і не змінював налаштувань сервера без явного дозволу автора.

## 4. Контроль достовірності

Для кожного розділу автор виконав:

1. звірку чисел і імен модулів із кодом (команди з `README.md` пакета: `npm test`, `npm run docs:check`, `npm run audit:i18n`, `npm run audit:ui`);
2. перевірку джерел за переліком, видалення тих, які не вдалося відкрити;
3. уточнення місць, позначених `[…]`;
4. [перевірку на плагіат у системі `[назва]`, результат `[%]`];
5. [перевірку тексту інструментом виявлення ШІ-тексту, якщо цього вимагає заклад: результат `[%]`; зверніть увагу, що такі інструменти ненадійні].

## 5. Відомі обмеження, пов'язані з ШІ

- Моделі можуть формулювати правдоподібні, але хибні твердження. Усі числа й назви в пакеті слід звіряти з кодом (колонка «Звідки» в `README.md`).
- Список літератури містить лише джерела, наявні в журналі дослідження проєкту, та загальновідомі документації; дати звернення й актуальність слід підтвердити.
- Вартісні оцінки й нормативні посилання в розділі 5 залишено для заповнення автором.
- Тексти потрібно переписати власним стилем там, де автор не може пояснити матеріал на захисті.
