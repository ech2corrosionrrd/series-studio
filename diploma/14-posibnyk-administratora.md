# ПОСІБНИК АДМІНІСТРАТОРА Й РОЗГОРТАННЯ

Документ описує розгортання, налаштування й експлуатацію Series Lab. Деталі й актуальні значення — у `docs/HOSTING.md`, `docs/DEPLOY-PLATFORM.md`, `docs/ECONOMY.md` і `.env.example`.

## 1. Режими роботи

| Режим | Призначення | Особливості |
|---|---|---|
| `SERIES_MODE=local` | ПК автора | теки репозиторію, без акаунтів, **лише loopback** (127.0.0.1) |
| `SERIES_MODE=public` | хост | вхід гаманцем, кредити, дані по гаманцях, оплата USDC (за потреби), Telegram (за потреби) |

Процес **не стартує**, якщо слухає не loopback і `SERIES_ALLOWED_HOSTS` порожній або `AUTH_DOMAIN` не входить у цей список.

## 2. Вимоги

- Node.js ≥ 22.13 (підтримуються 22 і 24; `npm run ci` запускається на встановленій версії); для контейнера — образ `node:24-alpine`.
- Docker і Docker Compose для хоста; зворотний проксі з HTTPS (Caddy).
- Домен; DNS-запис на сервер.

## 3. Налаштування середовища

Основні змінні публічного режиму (повний перелік — `.env.example`):

| Змінна | Навіщо |
|---|---|
| `SERIES_ALLOWED_HOSTS` | ім'я, яке вводять користувачі (наприклад, `lab.w3ir.io`) |
| `AUTH_DOMAIN`, `AUTH_URI` | домен і `https://` + домен: у тексті підпису входу |
| `AUTH_SESSION_SECRET` | секрет HMAC сесій; **без нього вхід вимкнено** |
| `AUTH_CHAIN_ID` | ланцюг у тексті SIWE (типово 8453) |
| `ADMIN_WALLETS` | хто бачить вкладку Адмін |
| `SERIES_ALLOWED_WALLETS` | запрошення: порожньо = увійти може будь-який гаманець |
| `SERIES_DATA_DIR` | каталог даних (у контейнері `/data`) |
| `WELCOME_CREDITS`, `GENERATION_RATE_LIMIT_PER_MINUTE`, `REFERRAL_BONUS_CREDITS` | кредити й ліміти |
| `SOLANA_PAY_RECIPIENT` | **публічна** адреса USDC; без неї оплата вимкнена |
| `SOLANA_RPC_URL` | читання мережі для звірки переказів |
| `IRYS_PRIVATE_KEY` | необов'язково: окремий гаманець **з малим балансом** для кнопки Arweave; не гаманець творця |
| Ключі рушіїв (`FAL_KEY`, `REPLICATE_API_TOKEN`, …) | лише ті, якими оператор готовий платити |
| `SERIES_SPEND_CAP_USD` | денна стеля витрат на ключі рушіїв (на хості може бути `off`) |
| `SERIES_TELEGRAM_BOT_TOKEN`, `SERIES_TELEGRAM_CHAT_ID` | сповіщення оператору |

**Правила безпеки:**

1. Файл секретів (`.env.series-lab`) — лише на сервері, не в репозиторії.
2. Приватного ключа гаманця отримувача USDC серверу не потрібно: достатньо публічної адреси.
3. Серверні платні ключі — окремий гаманець із малим балансом.
4. Cookie сесії на не-loopback адресі має прапорець `Secure`: перед процесом має бути HTTPS.

## 4. Запуск

### Без Docker

```
npm ci --omit=dev
# .env: SERIES_MODE=public, HOST=0.0.0.0, SERIES_ALLOWED_HOSTS, AUTH_DOMAIN, AUTH_URI, AUTH_SESSION_SECRET
npm run lab:serve
```

`npm start` ще й відкриває браузер: для хоста використовуйте `lab:serve`.

### Docker

```
docker build -t series-lab:local .
docker compose -f deploy/series-lab/docker-compose.yml up -d
```

Каталог даних на хості має бути доступний для запису uid 1000. Перевірка зовні: `GET /health` → `{"status":"ok","service":"series-lab"}`; сторінка входу — `/login`, студія — `/studio/`.

Скрипти `deploy/series-lab/`: `phase3.sh` (початкове розгортання staging; ім'я задається `SERVICE_HOST`, старе ім'я — `LEGACY_HOST`), `phase3-rollback.sh`, `reset-staging.sh`, `upload.sh`, `backup.sh`, `install-backup.sh`, `verify-backup.sh`, `setup-offsite.sh`. Прапорці `phase3.sh`: `OPEN_ACCESS=1`, `ENABLE_PAYMENTS=1`, `ENABLE_TELEGRAM=1`.

## 5. Вкладка «Адмін»

| Розділ | Що показує |
|---|---|
| Ресурси | які ключі «є» (лише наявність), кошик |
| Економіка | пакети, собівартість, виручка, різниця; періоди 7/30 днів і за весь час |
| Статистика | користувачі, платежі, воронка |
| Помилки | недавні збої генерації, перевірка підключень до рушіїв |

## 6. Резервне копіювання й відновлення

| Коли (UTC) | Що |
|---|---|
| щогодини | копія `users.db` (48) |
| щодня 03:15 | повний знімок (7 добових + 4 тижневих) |
| кожні 6 год | перевірка свіжості копії; перевірка заповнення диска |
| щонеділі | навчання відновленням (`verify-backup.sh drill`) |

Додатково `npm run backup:pull` (на ПК оператора) забирає копію по SSH. Відновлення з зашифрованої копії: `openssl enc -d -aes-256-cbc -pbkdf2 -pass env:BACKUP_PASSPHRASE -in users-ГГГГММДД-ГГХХ.tar.gz.enc | tar -xz`, потім перевірка `PRAGMA integrity_check`.

> Копія, яку ніхто не пробував відкрити, не є бекапом.

## 7. Моніторинг

- Робочий процес GitHub Actions `health.yml` кожні 15 хвилин виконує GET/HEAD до публічних адрес (зовнішній сигнал).
- Сповіщення в Telegram: платежі, реферальні бонуси, збої резервних копій, заповнення диска. Підсумки генерацій користувачів на публічному хості оператору **не** надсилаються.

## 8. Оновлення

1. Гілка від `main`, зміни через pull request; перед комітом: `npm test`, `npm run audit:i18n`, `npm run audit:ui`, `npm run docs:check`.
2. Після злиття — зібрати новий образ і перезапустити контейнер; дані на томі зберігаються.
3. Відкат — `phase3-rollback.sh` або попередній образ.
4. Раз на місяць: `npm audit --omit=dev`; відома вразливість `bigint-buffer` (без виправлення) задокументована в `docs/RECOMMENDATIONS.md`.

## 9. Типові проблеми

| Симптом | Причина | Дія |
|---|---|---|
| Процес завершується одразу | не задано `SERIES_ALLOWED_HOSTS` або `AUTH_DOMAIN` поза списком | задати змінні |
| Вхід неможливий | порожній `AUTH_SESSION_SECRET` | задати секрет |
| Підпис входу не збігається | `AUTH_DOMAIN`/`AUTH_URI` не збігаються з адресою в браузері | узгодити |
| Платіж не зарахувався | сума не збігається з унікальною сумою замовлення; закінчився строк замовлення; недоступний RPC | перевірити замовлення в `sol_orders`, RPC |
| Кнопка Arweave прихована | немає `IRYS_PRIVATE_KEY` | це нормально: використовувати `series upload --keypair` |
| Тест `studio-docs` падає з EPERM (Windows) | процес ще тримає файл | оновитися до версії з виправленням |

## 10. Дані користувачів і приватність

- Кнопка «Мої дані» видаляє файли й записи використання гаманця; облік грошей лишається (баланс, платежі, списання, реферальні винагороди).
- Умови користування й Політику конфіденційності опубліковано на сайті сервісу (бета-версія без юридичної експертизи).
- Сторонньої аналітики немає; журнали проксі зберігаються 30 діб (за політикою конфіденційності).
