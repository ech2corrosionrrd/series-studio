## 5.1 Модель ціноутворення в системі

Користувач бачить **кредити**; долари з'являються на поповненні (USDC у Solana) і в адмін-панелі (собівартість, маржа).

**Пакети кредитів** (за `docs/ECONOMY.md`):

| Пакет | USD | Кредити | $/кредит |
|---|---|---|---|
| Старт | 4,99 | 100 | ≈ 0,050 |
| Креатор | 14,99 | 400 | ≈ 0,038 |
| Профі | 29,99 | 1000 | ≈ 0,030 (найнижча ціна) |

**Правило підлоги.** `кредити = ceil(costUsd × 50)`: один кредит за $0,03 має покривати не менше ніж **1,5×** вартості виклику API. Це гарантує, що найдешевший пакет не продається нижче собівартості з запасом 50 %.

**Тариф рушіїв** (кредитів за кадр: чернетка / фінал / з референсом):

| Сімейство | Кредитів | Типова собівартість API |
|---|---|---|
| Flux (kontext, fal, schnell…) | 1 / 2 / 2–3 | ≈ $0,003–0,04 |
| Stability | 1 / 2 / 2–3 | ≈ $0,03–0,035 |
| OpenAI | 4 / 8 / 6–10 | ≈ $0,04–0,17 |
| Локальний GPU (ComfyUI, A1111) | `LOCAL_GPU_CREDIT_COST` (типово 1) | $0 за API |

**Ціна етапу:**

```
ціна_етапу = собівартість + фіксована_маржа
кредити   = ceil(ціна_етапу / STAGE_USD_PER_CREDIT)       (типово 0,03)
```

Генерація лишається на тарифі рушіїв; евристичний відбір — типово $0; архів, набір деплою й набір маркетплейсу — невеликі фіксовані суми (типово 1–2 кредити). Завантаження в Arweave додається лише тоді, коли користувач запускає його сам (його вартість платить гаманець користувача, а не сервіс).

**Безкоштовний шлях:** рушій `mock` і локальна робота без списань; новий перевірений гаманець отримує 20 вітальних кредитів (разово).

## 5.4 Окупність

```
Точка беззбитковості (кредитів) = (Постійні витрати за період) / (Ціна кредиту − Собівартість кредиту)
```

Для найдешевшого пакета «Профі»: ціна кредиту ≈ $0,03; для Flux-рушіїв собівартість кадру ≈ $0,003–0,04 за 1–3 кредити, тобто маржа на кредит додатна лише завдяки правилу підлоги ×1,5. Підставте реальні постійні витрати й очікуваний обсяг продажів.

## 5.5 Охорона праці та безпека в надзвичайних ситуаціях (шаблон)

1. **Умови праці користувача ПК.** Робота програміста й користувача системи проходить за персональним комп'ютером. Нормовані параметри робочого місця: освітленість, мікроклімат, шум, відстань до монітора, перерви в роботі. [Вкажіть значення за чинними санітарними нормами України.]
2. **Ергономіка інтерфейсу як частина безпеки.** Інтерфейс системи зменшує навантаження: поділ шляху на кроки, підказки при наведенні, двомовна довідка, адаптивна верстка для мобільних екранів; підтвердження небезпечних дій (видалення даних вимагає слова `DELETE`; кошик дозволяє відновлення).
3. **Електробезпека й пожежна безпека** робочого місця. [Типові вимоги.]
4. **Безпека в надзвичайних ситуаціях.** План дій при відключенні електроенергії, зв'язку; для системи — резервні копії (розділ 4.4), які дозволяють відновлення після збою обладнання.
5. **Інформаційна безпека як складова безпеки праці:** принцип «ключі не залишають ПК користувача»; відмова приймати приватні ключі; захист облікових даних.

## 5.6 Висновки до розділу

Ціноутворення в системі побудовано так, щоб жоден платний виклик не міг бути продано дешевше за 1,5× собівартості API; безкоштовний шлях (`mock`, локальний GPU) доступний без витрат. Економічні показники розробки й експлуатації потрібно уточнити власними даними; формули й параметри для цього наведено вище.
